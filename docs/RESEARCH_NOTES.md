# Research Notes

The profile and project standards use the following primary sources.

| Source | Applied decision |
| --- | --- |
| [GitHub: About repository READMEs](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes) | Keep the profile README concise, explain the work, and place it in a public repository with the same name as the account username. |
| [GitHub: Profile contributions reference](https://docs.github.com/en/account-and-profile/reference/profile-contributions-reference) | Treat the contribution graph as a record of real work. Commits need an account-associated email and must reach the default branch or `gh-pages` of a standalone repository to qualify. |
| [GitHub: Default community health files](https://docs.github.com/en/communities/setting-up-your-project-for-healthy-contributions/creating-a-default-community-health-file) | Keep reusable issue, pull request, contribution, and security guidance in a public `.github` repository when account-wide defaults are needed. |
| [CISA: Enhanced Visibility and Hardening Guidance](https://www.cisa.gov/resources-tools/resources/enhanced-visibility-and-hardening-guidance-communications-infrastructure) | Make logging, asset visibility, hardened management access, secure protocols, and configuration validation first-class project concerns. |
| [AWS: VPC security best practices](https://docs.aws.amazon.com/vpc/latest/userguide/vpc-security-best-practices.html) | Treat cloud network controls as deliberate designs: constrain traffic, inspect where appropriate, and document the security boundary. |

These sources guide the work; they do not imply certifications, employer affiliations, or production experience.
